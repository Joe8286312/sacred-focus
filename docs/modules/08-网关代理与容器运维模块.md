## 1. 模块概述与业务职责

### 1.1 模块定位
本模块是系统**生产环境交付、网络流量反代与运行时守护基座**。系统提供企业级标准的容器化编排方案，将前端静态资产、Node.js 运行时、SQLite WAL 存储与 Nginx TLS 网关有机整合，支持传统物理机、虚拟机与公网云服务器的一键部署与零宕机平滑升级。

### 1.2 核心业务职责
1. **Docker 多阶段构建 (Multi-Stage Build)**：
   - **Stage 1 (builder)**：基于 `node:22-bookworm-slim` 编译前端 Vue 3 + Vite 和后端 TypeScript；
   - **Stage 2 (prod-deps)**：纯净安装并编译生产原生 `better-sqlite3` 二进制依赖；
   - **Stage 3 (runner)**：提取纯净产物，精简镜像体积，剥离构建工具与 devDependencies；
2. **最小权限原则 (Least Privilege)**：
   - 生产容器严格采用非特权账号 `USER node` 运行，规避特权外溢与容器逃逸；
3. **Nginx 网关与 TLS 1.3 反向代理**：
   - 全链路加密：强制 HTTP 301 重定向至 HTTPS；
   - 健康检查豁免：`/api/health` 探针豁免 HTTPS 重定向，确保容器拨测不发生死锁；
   - 协议标头透传：准确透传 `Host`、`X-Real-IP`、`X-Forwarded-For` 与 `X-Forwarded-Proto https`；
   - 大文件上传支持：配置 `client_max_body_size 20M`，保障全量备份包导入不受阻；
4. **日志轮转与健康自愈**：
   - 配置 `json-file` 日志轮转（`max-size: 20m`, `max-file: 3`），防磁盘写满；
   - 容器内置每 30 秒自动执行的 `curl /api/health` 健康检查；
5. **版本化离线包交付与热更新脚本**：
   - 提供跨平台打包（`.tar`）与虚拟机平滑热更新运维脚本。

## 4. 关键配置与工程规范

### 4.1 Nginx 网关反代标准标头
```nginx
# nginx/conf.d/default.conf
proxy_pass http://sacred-focus:3000;
proxy_http_version 1.1;
proxy_set_header Host $host;
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
proxy_set_header X-Forwarded-Proto https; # 确保后端 Cookie 开启 Secure
```

### 4.2 Dockerfile 最小特权与健康探测
```dockerfile
# Dockerfile 生产运行时
USER node
HEALTHCHECK --interval=30s --timeout=5s --start-period=10s --retries=3 \
  CMD curl -f http://127.0.0.1:3000/api/health || exit 1
CMD ["node", "backend/dist/server.js"]
```

## 5. 跨模块协同关系

1. **为【01-身份认证模块】提供网络上下文**：
   - 通过透传 `X-Forwarded-Proto https`，触发后端的 Cookie 自适应标记；
   - 透传真实客户端 IP 供限流器与蜜罐使用；
2. **为【02-数据库模块】提供物理持久化挂载**：
   - 挂载 `./data:/app/data`，保证容器销毁、重建、升级过程中 SQLite 数据 100% 留存；
3. **协同【06-整机迁移模块】**：
   - 通过 `client_max_body_size 20M` 放行整机 JSON 备份包的上传。
