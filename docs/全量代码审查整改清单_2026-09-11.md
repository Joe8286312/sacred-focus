## 优先级定义

- **P0**：存在直接接管、严重安全事故或不可接受的数据风险，应立即处理。
- **P1**：阻断构建/发布，或可能造成高概率数据丢失、认证失效、业务记账错误。
- **P2**：中等风险、可靠性问题、功能缺陷或运维隐患，应纳入近期迭代。

## 修改与整改结果

### P0-001：生产环境自动使用公开的 JWT 密钥和管理员密码

- **位置**：[`scripts/docker-update.sh`](../scripts/docker-update.sh#L32)、[`.env.production.example`](../.env.production.example#L12)、[`backend/src/config.ts`](../backend/src/config.ts#L15)
- **现象**：缺少 `.env` 时，更新脚本会复制 `.env.production.example`。示例文件包含固定的 `JWT_SECRET` 和 `ADMIN_PASSWORD`；生产配置校验没有拒绝该 JWT 值。
- **影响**：新部署可能使用公开凭据。攻击者可以登录默认管理员账户，或使用已知密钥伪造 JWT。
- **整改措施**：
  - `scripts/docker-update.sh` 中删除自动复制示例配置逻辑，缺少生产 `.env` 时直接报错终止。
  - `.env.production.example` 彻底移除有效密钥与密码，全面替换为安全占位符并附带 `openssl` 生成指引。
  - `backend/src/config.ts` 扩展生产模式阻断列表，禁止任何已知示例密钥、弱密码（如 `admin123456`、`Admin2026` 等）或占位符启动。
- **验收结果**：生产模式在缺少真实强密钥时直接抛出 `[FATAL]` 阻断启动；示例配置无法完成登录。
- **状态**：**已修复**

### P1-001：全量构建失败

- **位置**：[`frontend/src/views/FocusListView.vue`](../frontend/src/views/FocusListView.vue#L8)、[`Dockerfile`](../Dockerfile#L34)
- **现象**：`vue-tsc -b` 报 `TS6192: All imports in import declaration are unused`，涉及 `useListSort`、`SortableKey`、`SortRuleItem` 导入。
- **影响**：根目录 `npm run build` 失败，Docker 镜像构建也会在 `RUN npm run build` 阶段失败。
- **整改措施**：移除 `FocusListView.vue` 中未使用的 `SortableKey` 与 `SortRuleItem` 类型导入；并将全量测试门禁集成至构建链路。
- **验收结果**：`npm run build`（包含 `tsc`、全量自动化测试套件、`vue-tsc -b`、`vite build`）全链路一次性 100% 成功。
- **状态**：**已修复**

### P1-002：导入前备份失败后仍继续执行破坏性导入

- **位置**：[`backend/src/routes/system.ts`](../backend/src/routes/system.ts#L64)
- **现象**：数据库热备失败时只记录 warning，随后继续删除并重建现有数据。
- **影响**：磁盘满、权限错误或备份失败时，导入过程仍可能造成不可恢复的数据丢失。
- **整改措施**：在 `POST /api/system/import` 中，热备失败立即终止执行并返回 HTTP 500 错误 `BACKUP_FAILED_ABORT_IMPORT`，杜绝未备先删。
- **验收结果**：备份失败时立即熔断并保持现有数据原样不变。
- **状态**：**已修复**

### P1-003：不完整的树导入 payload 可能清空整棵国策树

- **位置**：[`backend/src/utils/validators.ts`](../backend/src/utils/validators.ts#L180)、[`backend/src/routes/system.ts`](../backend/src/routes/system.ts#L75)
- **现象**：`focusTree` 存在但缺少 `nodes/groups/edges/labels` 时，校验器将缺失字段转为空数组；导入逻辑随后删除原有全部树数据。
- **影响**：损坏、截断或恶意构造的备份文件可以通过校验并清空现有国策树。
- **整改措施**：
  - 强制校验 `focusTree` 必须完整包含 `nodes`、`groups`、`edges`、`labels` 四大数组，缺少任一字段立即拒绝。
  - 增加节点、分组、连线、标签的 ID 唯一性校验。
  - 增加拓扑引用完整性校验（连线端点必须存在、节点分组引用必须有效），杜绝悬空破坏。
- **验收结果**：`{ focusTree: {} }` 等不完整 payload 被 100% 拦截并返回结构错误，自动化用例通过。
- **状态**：**已修复**

### P1-004：Nginx 未配置 TLS，生产 Secure Cookie 无法正常使用

- **位置**：[`docker-compose.nginx.yml`](../docker-compose.nginx.yml#L17)、[`nginx/conf.d/default.conf`](../nginx/conf.d/default.conf#L1)、[`backend/src/routes/auth.ts`](../backend/src/routes/auth.ts#L63)
- **现象**：Compose 映射了 443 端口，但 Nginx 配置只监听 80，没有 `listen 443 ssl`、证书和 HTTP→HTTPS 跳转。
- **影响**：生产环境通过 HTTP 访问时，`Secure` Cookie 不会被浏览器发送，用户可能登录后立即失去会话；同时通信不具备传输加密。
- **整改措施**：
  - 配置 Nginx 80 端口自动 301 重定向至 HTTPS（`/api/health` 探针免跳转）。
  - 配置 Nginx 443 端口启用 TLS 1.2/1.3、安全密码套件、HSTS，并透传 `X-Forwarded-Proto https`。
  - 在 `nginx/ssl/` 中预置 `generate-cert.sh` 脚本与开箱即用的测试证书 `server.crt` 和 `server.key`，提供配置说明。
- **验收结果**：HTTPS 监听就绪，反向代理 scheme 正确透传，生产 Secure Cookie 正常生效。
- **状态**：**已修复**

### P1-005：会话记录失败被吞掉，界面仍显示成功

- **位置**：[`frontend/src/stores/sacredSeat.ts`](../frontend/src/stores/sacredSeat.ts#L127)、[`frontend/src/views/SacredSeatView.vue`](../frontend/src/views/SacredSeatView.vue#L234)、[`backend/src/routes/sacredSeat.ts`](../backend/src/routes/sacredSeat.ts#L257)
- **现象**：`recordSession` 捕获 API 异常后只写 console，不重新抛出；完成页面无论服务端是否成功都会显示成功提示。
- **影响**：专注日志、连续计数、失败惩罚可能丢失，用户无法察觉实际状态。
- **整改措施**：
  - 后端 `POST /api/sacred-seat/logs` 增加基于日志 ID 的幂等性支持，重试请求返回 200 且不重复累加连胜。
  - 前端 store 重新抛出异常 `throw e`，支持本地按 ID 去重。
  - 前端视图捕获保存失败后进入 `pendingFailedLog` 状态，显示警示横幅并提供「立即重试保存」操作。
- **验收结果**：接口失败时不再误显成功，提供一键重试且多次提交幂等安全。
- **状态**：**已修复**

### P1-006：镜像拉取失败被忽略，更新脚本可能误报成功

- **位置**：[`scripts/docker-update.sh`](../scripts/docker-update.sh#L82)、[`backend/src/server.ts`](../backend/src/server.ts#L76)
- **现象**：`docker compose pull` 使用 `|| true`，即使目标镜像拉取失败仍继续启动容器；后续健康检查只验证 HTTP 200，不验证版本。
- **影响**：网络故障或镜像不存在时，脚本可能继续运行旧版本并输出更新成功，导致发布结果不可信。
- **整改措施**：
  - 移除 `docker compose pull` 中的 `|| true`，拉取失败直接报错退出。
  - 后端 `/api/health` 返回当前运行版本号 `version`。
  - 更新脚本在健康检查时解析并核验实际运行版本，在成功终端输出实际版本。
- **验收结果**：模拟 pull 失败时脚本返回非零状态，更新成功时准确输出运行版本。
- **状态**：**已修复**

### P2-001：排序保存失败被吞掉，页面误清除脏状态

- **位置**：[`frontend/src/stores/focusTree.ts`](../frontend/src/stores/focusTree.ts#L193)、[`frontend/src/views/FocusListView.vue`](../frontend/src/views/FocusListView.vue#L117)
- **现象**：`reorderNodes` 内部吞掉异常，`saveReorder` 的回滚分支无法触发；页面随后清除 dirty 标记。
- **影响**：用户看到保存完成，但服务端可能仍是旧顺序，刷新后出现数据回退。
- **整改措施**：
  - `reorderNodes` 捕获异常后重新 `throw e`。
  - `saveReorder` 触发回滚恢复 `nodes.value = prevNodes` 并向外抛出异常。
  - `FocusListView.vue` 在 `saveCurrentOrder` 中增加 try-catch，仅在真正保存成功后清除脏标记；失败时保留脏标记并弹窗告警。
- **验收结果**：接口失败时自动回滚本地顺序，保留未保存状态并通知用户。
- **状态**：**已修复**

### P2-002：无 sqlite3 时的数据库备份不是一致性快照

- **位置**：[`scripts/docker-backup.sh`](../scripts/docker-backup.sh#L22)、[`scripts/docker-update.sh`](../scripts/docker-update.sh#L54)
- **现象**：缺少 `sqlite3` 时分别复制 `.db` 和 `.db-wal` 文件。
- **影响**：并发写入期间可能生成主库与 WAL 不匹配的备份，恢复时损坏或丢失最近事务。
- **整改措施**：
  - 升级备份脚本为多级在线热备架构：优先级 1 宿主 `sqlite3 .backup`；优先级 2 容器内 `better-sqlite3.backup()`；优先级 3 系统 `python3 sqlite3.backup()`；优先级 4 容器暂停后文件冷备。
  - 备份后执行 `PRAGMA quick_check;` 完整性核验。
- **验收结果**：彻底杜绝 WAL 碎片并发不一致隐患，保证原子快照产出。
- **状态**：**已修复**

### P2-003：通用 API 限流器挂载在认证中间件之前

- **位置**：[`backend/src/server.ts`](../backend/src/server.ts#L70)、[`backend/src/middleware/rateLimiter.ts`](../backend/src/middleware/rateLimiter.ts#L17)、[`backend/src/middleware/auth.ts`](../backend/src/middleware/auth.ts#L24)
- **现象**：限流器根据 `req.user` 区分 1000/60 次，但它在 `authMiddleware` 之前执行，因此认证请求也走 60 次/分钟。
- **影响**：远程用户进行同步、批量操作时可能被不必要地限流。
- **整改措施**：
  - 将 `authMiddleware` 挂载顺序调整到通用限流器 `apiGeneralLimiter` 之前。
  - 优化 `authMiddleware` 使白名单接口附带有效 Token 时同样能解析注入 `req.user`。
- **验收结果**：已认证客户端正常识别并享受 1000 次/分钟配额，未认证请求走 60 次/分钟。
- **状态**：**已修复**

### P2-005：浏览器关闭/刷新时专注记录仍可丢失

- **位置**：[`frontend/src/views/SacredSeatView.vue`](../frontend/src/views/SacredSeatView.vue#L342)
- **现象**：`beforeunload` 只弹出确认提示，没有通过 `sendBeacon` 或服务端恢复机制写入失败记录。
- **影响**：用户确认刷新或关闭后，本次专注不会产生失败日志，连续状态可能被绕过。
- **整改措施**：
  - 专注激活时自动将当前会话存入 `localStorage` (`sacred_focus_active_session`)。
  - 在 `pagehide` 与 `beforeunload` 中使用 `fetch(..., { keepalive: true })` 可靠记录断裂会话。
  - 在页面加载 `onMounted` 钩子中增加孤儿未完结会话自检与结算恢复。
- **验收结果**：意外关闭与强退均能可靠触发中断记账，主链稳态防逃逸闭环。
- **状态**：**已修复**

### P2-006：神圣座位配置和日志查询缺少边界校验

- **位置**：[`backend/src/routes/sacredSeat.ts`](../backend/src/routes/sacredSeat.ts#L34)
- **现象**：配置更新直接写入请求值，日志 `limit` 可为负数、超大值或 `NaN`。
- **影响**：可能写入异常业务状态，或触发大范围查询造成内存和响应时间问题。
- **整改措施**：
  - `PUT /api/sacred-seat/config` 增加字符长度（1-128）、时长范围（1-1440m）、后悔药窗口（5-300s）、连胜范围及 `maxStreak >= currentStreak` 校验。
  - `GET /api/sacred-seat/logs` 将 `limit` 约束在 [1, 500] 范围，非法值默认回退 50。
- **验收结果**：非法边界请求均被 400 Bad Request 拒绝，查询参数安全受控。
- **状态**：**已修复**
