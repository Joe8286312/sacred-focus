## 一、 系统总体架构与设计原则

### 1.1 核心理论与系统定位

本系统将自制力问题抽象为行为经济学中的**双曲贴现变换**与系统动力学中的**稳态闭环**：

```
                              ┌────────────────────────────────────────┐
                              │        RSIP 宏观递归稳态 (国策树)        │
                              │   全天候节点 · 连线流水 · 版本演化日志    │
                              └───────────────────┬────────────────────┘
                                                  │ 指导 / 派生
                                                  ▼
┌──────────────────────────────────────────────────────────────────────┐
│                     CTDP 微观启动与专注 (神圣座位)                     │
│                                                                      │
│    【预约链】                    【专注倒计时】             【判例法典】   │
│   (线性时延平移)                (非线性价值压缩)           (下必为例定性)  │
│   预约倒计时结束 ──────确认就位────► 深度心流 ──────结算归零──► 增量判例录入│
│   (可调 5~30m)                  (默认 60m)                (事后唤醒提示) │
└──────────────────────────────────────────────────────────────────────┘
```

1. **CTDP 链式时延系统**：
   - **神圣座位（非线性价值压缩）**：设定神圣信物，专注状态与普通状态物理隔离；建立工作量证明链条（#1, #2...），违规即全链清零。
   - **线性时延（预约链）**：避开当下 $\tau=0$ 处无穷陡峭的贴现阻抗，以预定倒计时平移起始时刻。
   - **下必为例（判例法定性）**：面对灰色试探，以“终身永久放行”的极高摩擦力反向消灭侥幸心理。
2. **RSIP 稳态闭环系统**：
   - **国策树全域流水线**：将早起、日间攻坚、体能充能与极夜就寝封装为可点亮、可扩展的有向图。
   - **版本化演化**：允许试错，但必须记录演化日志，支持版本安全回滚。

### 1.2 UI/UX 极简设计原则与双主题规范

由于本系统核心服务于“注意力稀缺与高对抗专注场景”，界面设计确立以下底线：

1. **绝对极简，剔除噪音**：
   - 拒绝多余的装饰性动效、图表炫技、背景装饰视频。
   - 坚决**不内置白噪音播放器**（避免用户把宝贵的决策精力消耗在“挑歌、选氛围音”上；如需白噪音，由用户在系统底层独立播放）。
2. **双模式自适应高对比度设计**：
   - **深色模式（极夜模式，默认夜晚或按时间触发）**：
     - 背景色：纯黑（`#000000` 或 `#0A0A0C`），适配 OLED 屏幕，降低暗光环境视觉刺激。
     - 文字：白灰层次（主文本 `#EDEDED`，次级 `#8A8A93`）。
     - 节点：纯黑底色 + 高饱和细边框高亮（点亮为天青/金黄微光，未点亮为幽暗石墨灰）。
   - **浅色模式（日光模式）**：
     - 背景色：极简纸感浅灰白（`#F8F9FA`），内容卡片为纯白（`#FFFFFF`）。
     - 文字：高对比墨黑（`#111827`）与深灰（`#4B5563`）。
     - 节点：白底黑字 + 高对比实色边框。
   - **切换策略**：支持 `跟随系统` / `按时间段自动切换（如 07:00 浅色 / 22:30 深色）` / `手动常驻`。

## 二、 模块一：神圣座位（CTDP 引擎）详细设计

### 2.1 专注倒计时（零干扰心流设计）

* **界面要素**：
  * 全屏极简显示：中央超大等宽时钟字体（`HH:MM:SS` 或 `MM:SS`）。
  * 顶部极淡文字展示当前神圣信物（如：`信物生效中：主力机开启专注模式`）。
  * 底部仅保留一个轻量级操作区：【放弃退出】（需二次确认防手滑）。
* **倒计时归零响应（关键机制）**：
  * **传统倒计时的弊病**：闹铃大作、页面剧烈晃动闪烁或弹出全屏结算弹窗，强行将用户从心流深渊中惊醒，摧毁了超额专注的可能。
  * **本系统设计**：
    * 倒计时到达 `00:00:00` 时，**静音且不改变界面背景色彩**。
    * 倒计时数字停止在 `00:00:00`，或转为微弱低对比度的超额计时器（如 `+ 04:15`），鼓励用户顺水推舟继续深潜。
    * 保持界面极度安宁，不产生任何主动打扰。

---

### 2.2 个性化神圣座位设定

用于存放和更新用户个人的行为学物理锚点。

* **配置项清单**：
  1. **神圣信物 (Sacred Token)**：字符串（例：`主力机开启专注模式`、`深呼吸3次并戴上蓝色帽子`）。
  2. **预约启动信号 (Reservation Signal)**：字符串（例：`反手拍手轻声说换人`、`打响指`）。
  3. **标准专注时长 (Standard Focus Duration)**：数值，单位分钟（默认 `60` 分钟）。
  4. **后悔药免责窗口 (Regret Window)**：数值，单位秒（默认 `30` 秒）。
  5. **超时顺延记录策略**：布尔值（是否将超过预设时长的专注时间一并累加计入总专注时长）。
* **交互规则**：
  * 提供统一配置弹窗/抽屉。
  * 点击【保存】应用配置；点击【取消】立即丢弃未保存的草稿并还原为原设定。

---

### 2.3 下必为例判别记录（延迟无感采集机制）

“下必为例”是捍卫规则完整性、杜绝侥幸破窗的宪法机制。

#### 采集时机与交互流（关键设计）
1. **专注执行期间**：严禁打扰，绝不弹出任何判例输入框。
2. **倒计时归零时**：保持 `00:00:00` 画面不变，不弹出提醒。
3. **延迟触发结算契机**：
   * 当用户完成了深度专注，主动拿起手机或在电脑上**首次点击页面任意位置**时，系统捕捉到该“唤醒动作”，判定用户已退出心流。
   * 此时页面弹出温和而醒目的结算弹窗：
     > **🪑 本次神圣专注已圆满结束**  
     > 在刚才的专注过程中，是否发生了模糊、突发或疑似违规的行为，需要记录【下必为例】判例？
   * 提供两个明确动作选项：
     * **【无争议，直接完成】**：不记录判例，直接结算本次专注成功。
     * **【记录判例法典】**：唤出判例录入卡片。
4. **判例录入卡片字段**：
   * `判定日期`：自动填入当前日期（支持微调）。
   * `行为描述`：文本输入（例：“中途起身接水”、“用浏览器查阅英文文档”）。
   * `裁决结果`：单选切换 —— **【允许】** 或 **【禁止】**。
   * `裁决说明与边界约束`：文本输入（例：“允许条件：水杯在视野内，接水必须在 1 分钟内返回，严禁携带手机；否则判定为违规”）。
5. **判例法典库**：
   * 独立页面提供历史判例检索与列表展示，支持按“允许/禁止”标签快速过滤，作为日常执行的终身参照法。

### 2.4 神圣座位实践记录与 30 秒后悔药机制

* **自动化后台日志采集**：
  * 记录字段：`本次会话ID`、`开启时间戳`、`结束时间戳`、`预设时长`、`实际执行时长`、`结算状态 (SUCCESS / FAIL / REGRET)`。
* **状态机分支判断**：

```
                用户点击【开启神圣座位】
                           │
                           ▼
                    倒计时正式启动
                           │
             ┌─────────────┴─────────────┐
             ▼                           ▼
      运行时间 < 30 秒            运行时间 >= 30 秒
             │                           │
     用户点击【放弃退出】        ┌─────────┴─────────┐
             │                   │                   │
             ▼                   ▼                   ▼
    触发【后悔药国策】       自然坚持到结束       中途主动点击放弃
    - 不计入违规断链       - 判定为 SUCCESS      - 弹出清零严正警告
    - 不增加工作量编号     - 主链节点加 1        - 二次确认后断链
    - 纯净退出无负罪感     - 更新最高连胜记录    - 节点强制清零归 #0
```

* **主链连胜计数器 (Proof of Work)**：
  * 界面显眼位置呈现当前主链进度标签：`当前节点：#N`，以及 `历史最高纪录：#MAX`。
  * 每次成功完成且无违规中断，`#N` 自增 1；一旦发生超过 30 秒的违规放弃，`#N` 强制重置为 `#0`。

### 2.5 预约链（动态线性时延与自动衔接）

用于解决“神圣座位过于庄严沉重导致不敢启动”的前额叶阻抗。

* **动态时长调节器**：
  * 在预约链主卡片上，无需打开弹窗，直接提供快捷调节按钮：`[+5m]`、`[+10m]`、`[+15m]` 或数字微调滑块，默认 `15:00`。
  * 允许用户根据当前所处的现实场景自由指定本次平移时间。
* **倒计时结束响应**：
  * 预约倒计时归零时，系统播放清脆的**音频提示音**，并触发设备震动（若移动端支持）。
  * 界面呈现全屏高对比醒目提示卡片：
    > ⏰ **预约时间已到！启动信号已点火**  
    > 请即刻就位，触发神圣信物。
  * 提供大尺寸主行动按钮：**【确认就位，开始专注】**。
  * 用户点击确认后，**页面无缝自动跳转至「专注倒计时」页面**，直接进入专注待命或点火状态。

## 三、 模块二：国策树（RSIP 引擎）详细设计

### 3.1 国策树画布可视化与交互规范

画布是系统中最具视觉冲击力与操作深度的模块。

#### 1. 节点（Node）视觉构成与极简无装饰原则
每个国策节点设计为一个圆角矩形卡片（固定基准尺寸：宽 `180px`，高 `80px`）：
* **极简零认知负担原则（严格禁止装饰性 Emoji）**：
  * **设计初衷**：新建国策若允许或推荐选择 Emoji 图标，用户为保持风格一致性往往会花费大量时间思考“选哪个图标合适”，大幅推高了新建与迭代国策的心理阻抗与决策成本。
  * **规范约束**：国策编码（Code）、国策名称与场景/触发时间中**彻底杜绝任何装饰性 Emoji 图标**，一律采用纯净文字。
  * **Emoji 独占用途**：Emoji 图标**仅严格保留用于全局状态指示**（如 🟢 已点亮 / ⚪ 熄灭待命 / ❄️ 水密隔舱冻结）。
* **卡片布局要素**：
  * **左上角**：国策唯一纯文本代码（如 `R0`, `M1`, `F3`, `N7`）加粗呈现。
  * **右上角**：状态指示灯（🟢/⚪/❄️）与等级标签（`Lv.当前/最高`，如 `Lv.1/3`）。
  * **居中主标题**：国策纯文本名称（如 `离地起爆`、`神圣寝域`），字号 `15px` 粗体。
  * **下沿标签栏**：纯文本场景/触发时间（如 `07:30`、`闹钟后3m`、`全天候`）。

```
┌───────────────────────────────┐
│ M1                  🟢 Lv.1/3 │
│ 离地起爆                      │
│ ───────────────────────────── │
│ 闹钟响后3分钟内离开床铺       │
└───────────────────────────────┘
```

#### 2. 状态渲染逻辑
* **点亮状态（Lit）**：拥有极具辨识度的状态切换反馈。不仅边框加粗高亮（翡翠绿 `#10B981`），**整张卡片背景色均切换为清新浅绿色**（浅色模式下采用 `#E6F4EA` 清爽柔和浅绿配合深绿文字，深色模式下采用透光暗翡翠渐变），在深浅双模式下均极具视觉冲击力与心流达成感。
* **熄灭状态（Unlit）**：边框为低对比度浅灰，文字适度弱化，代表待点亮或日常参数调试中。
* **冻结状态（Frozen / 水密隔舱）**：边框采用冰蓝色虚线，提示系统处于豁免结算态。

#### 3. 双模式交互流（彻底解除右键拦截，杜绝双击视角抖动）
* **模式 A：展示模式 (View Mode，默认态)**：
  - 防误触：拖拽整个画布只执行平移，不位移单个节点；禁用双击自动缩放聚焦（`:zoom-on-double-click="false"`），杜绝晃动。
  - **单击节点**：即刻切换该国策的【点亮 / 熄灭】状态，并同步持久化至后台。
  - **双击节点**：屏幕中央优雅唤出国策【详细规范卡】，展示动作指令、失败判定与心理机制。
  - **完全去除右键自定义逻辑**：右键完整归还浏览器原生系统菜单。
* **模式 B：编辑模式 (Edit Mode，顶部居中开关切换)**：
  - 允许按住节点或分组标题栏任意拖拽调整物理坐标。
  - **单击节点**：仅选中当前节点，不触发点亮。
  - **双击节点**：呼出【编辑国策表单】修改全部属性。
  - 鼠标悬停节点边缘时，暴露上下左右 4 个连接桩，以**中心对称向外微扩放大**（杜绝偏心偏移失真）。
  - **两步点击精准相连 (Click-to-Connect)**：先后点击两个连接桩（先点击起始桩，后点击目标桩），即使两节点跨越整个屏幕极远距离，亦可零成本秒连，且连线有向箭头（起始 ➔ 目标）100% 确定无倒置。
  - **顶部控制条严格网格居中**：采用 `1fr auto 1fr` 三列绝对栅格布局，模式切换开关永恒锁定在视口 50% 几何正中心，绝不因编辑按钮显隐而产生哪怕 1 像素的横向跳变。

### 3.2 节点分组（外框）与智能正交避障连线

#### 1. 分组外框（Grouping Subgraph Frame）与独立节点规则
* **默认独立无外框**：新建国策时，其归属分组默认置空（`groupId: null`）。独立国策在画布上为自由节点，**不产生任何多余外框**，保持画布清爽。
* **分组外框表现与自定义主题**：
  * 概念对应国策树中的各层级纵深（如：【早起破晓组】、【专注作战组】、【夜间极夜组】）或用户自定义逻辑组。
  * **自定义主题色**：支持用户为每个分组自由指定主题色（支持预设橙红、湛蓝、翠绿、幽紫、钴蓝，或任意 HEX/HSL 强调色）。
  * 外框呈现为半透明虚线圆角框，顶部带有纯文本分组标题标签。
  * **内部点击穿透机制**：外框内部空白区域采用 `pointer-events: none` 穿透设计，仅标题栏与边框捕获拖拽平移事件。确保**组内节点间的连线可以自由被鼠标精准悬浮、选中与删除**，彻底解决图层遮挡问题。
* **分组外框全层级连线能力（跨组拓扑）**：
  * **外框连接锚点**：每个分组外框本身具有完整的上下左右 4 个磁吸连接锚点。
  * **全场景多维拓扑支持**：
    1. **分组 ➔ 分组 (Group-to-Group)**：整组流水线衔接（例如：整个【早起破晓组】指向【专注作战组】）；
    2. **分组 ➔ 单个独立国策 (Group-to-Node)**：例如整个【夜间极夜组】流转至独立的【N7 神圣寝域】；
    3. **单个独立国策 ➔ 分组 (Node-to-Group)**：例如独立的【R0 水密隔舱】宪法国策跨组指向整个【日间作战组】；
    4. **节点 ➔ 节点 (Node-to-Node)**：基础的标准单体依赖连线。

#### 2. 智能正交避障连线系统（Orthogonal Router with Obstacle Avoidance）
* **锚点吸附**：每个节点与分组外框均具备 Top、Bottom、Left、Right 4 个连接点。支持长距离两步点击相连或鼠标拖拽磁吸。
* **正交避障路由算法**：
  * 严禁出现贯穿第三方节点、横穿其他外框文本区域的“斜拉乱线”。
  * 连线算法采用 **正交折线布线 (Manhattan Routing)**，线段仅以水平和垂直方向延伸。
  * 算法引入碰撞盒检测，遇到中间障碍节点时自动向外扩折弯绕行，转角处带 `r=4px` 圆角，确保图面清晰利落。
* **连线类型**：
  * **实线箭头**：表示硬性顺序流水线（如 `M1 -> M2`）。
  * **虚线箭头**：表示跨组弱关联、代偿赎买或防御分支（如 `R2 -.-> L1`、`F1 -.-> N7`）。
* **连线删除交互**：
  * ① 选中连线后，在折线精确几何中心位置浮现**高精度矢量 SVG 叉号图标**，微阴影红底圆形徽章，点击即删。
  * ② 选中连线后，直接按下键盘 `Backspace` 或 `Delete` 键立即删除。
  * ③ 双击连线直接触发删除。

### 3.3 国策列表展示与多维排序管理

列表页与画布互为表里：画布主张空间结构与直观流程，列表页主张密集数据审阅、批量状态管理与快捷操作。

#### 1. 列表列字段排布
1. **极简拖拽色块手柄**：前端采用极简的纯色色块条（可着主题色或低调素灰），替代笨重的拖动图标；电脑端支持鼠标直接按住色块拖曳排序，触控端支持长按色块拖拽。
2. **纯文本代码**：如 `R0`、`M1`、`F3`（彻底杜绝装饰 Emoji）。
3. **国策名称**。
4. **所属分组**：带主题色微标签（未分组则显示“独立国策”）。
5. **触发时间 / 场景**：纯文本描述（如 `07:30`、`闹钟后3m`、`全天候`）。
6. **等级进度**：展示当前等级与最高等级（格式：`Lv.当前 / 最高`，如 `Lv.1 / 3`，升满高亮显示 `MAX`）。
7. **状态指示**：仅使用状态指示点（🟢 / ⚪ / ❄️）直观反映点亮态。
8. **操作项**：编辑详情、删除。

#### 2. 便捷点亮与查阅交互（摆脱微小按钮）
为防止用户在移动端或快速浏览时“必须要死抠微小的开关或按钮”产生烦躁感，列表行支持全局手势与键鼠映射：
* **无障碍快速点亮 / 熄灭**：
  * **桌面端**：鼠标直接**双击列表行任意空白区域**，立即切换该国策的点亮/熄灭状态；
  * **移动端**：手指**快速双击列表行**，瞬间完成点亮切换，伴随微弱触觉震动反馈。
* **快速查看与编辑详细规范卡**：
  * **桌面端**：鼠标在列表行上**双击右键** 或 **连续快速三击左键**，直接从右侧滑出或居中弹出该国策的完整详细规范卡；
  * **移动端**：手指**长按列表行 500ms** 或 **快速三击行**，直接弹出规范卡。
* **单击行**：仅做行高亮选中，并在底部弹出辅助操作栏。

#### 3. 排序保存与临时排序还原机制（双态排序器）
针对“用户既需要精心定制默认基准顺序，又需要临时按时间/等级查找国策”的高频需求，设计**基准保存与临时排序还原机制**：
* **基准自定义排序（Saved Custom Baseline）**：
  * 用户通过鼠标/手指拖动极简色块手柄调整出的个性化物理排列顺序。
  * 默认规则：新创建的国策自动追加至基准顺序最末尾。
* **临时多维动态排序**：
  * 用户可随时点击表头或切换临时视图：
    * **按分组聚类排序**：相同分组自动合并归拢，独立国策置顶或置底。
    * **按触发时间排序**：识别时间与偏移量，配合配置开关：**【全天候/无时间点国策置顶】** 或 **【置底】**。
    * **按等级排序（当前等级/最高等级）**。
    * **按点亮状态过滤**。
* **【还原为保存的顺序】与【保存当前排序】按钮**：
  * **临时排序还原**：当用户在临时排序中查找完国策后，列表顶部常驻呈现 **【🔄 还原为保存的顺序】** 按钮，一键清空临时排序规则，恢复到之前保存的个人基准序列，不破坏原有的拖拽成果。
  * **排序固定保存**：若用户觉得某次按时间排序或拖动后的排列非常理想，可点击 **【💾 保存当前排序为默认】**，将当前状态持久化写入为新的基准排序。

### 3.4 国策演化日志与 5 版本防震荡环形缓存

本功能对应 RSIP 的“递归迭代”精髓，为国策树赋予类似 Git 的版本控制与回退能力。

#### 1. 保存触发演化提交流程
当用户在画布或列表修改了国策树结构（增删改节点、改动连线）并点击保存时，系统拦截并弹出【演化版本归档】窗口：
* **版本类型选择**：
  * **大版本演化 (Major Release)**：核心架构重构（如 `v1.0 -> v2.0`）。大版本号加 1，小版本号重置清零。
  * **小版本演化 (Minor Tuning)**：日常参数微调与节点修剪（如 `v1.0 -> v1.1`）。大版本号保持不变，小版本号加 1。
* **演化日志备注 (Changelog Notes)**：文本输入，记录本次微调的核心对策与心得（如：“在晨起组增加30分钟手环禁娱倒计时”）。

#### 2. 五版本防震荡环形快照机制 (5-Slot Ring Buffer with Stable State Pointer)

为防止存储无限膨胀并提供安全试错后悔药，系统在底层构建 5 槽位历史快照管理：

```
                    ┌───────────────────────────────┐
                    │     5-Slot Snapshot Buffer    │
                    ├───────┬───────┬───────┬───────┤
                    │ Slot0 │ Slot1 │ Slot2 │ Slot3 │ Slot4 │
                    │ v1.0  │ v1.1  │ v1.2  │ v1.3  │ v2.0  │
                    └───────┴───────┴───▲───┴───────┴───────┘
                                        │
                               Active Pointer = Slot2 (当前激活版本)
```

* **缓存结构**：固定存储最多 5 个历史全量树结构快照。
* **回滚逻辑 (Rollback)**：
  * 用户发现近期版本阻力太大或执行崩溃，可查看历史快照并点击【回滚到此版本】。
  * **指针移动原则（关键防耗尽设计）**：
    * 回滚操作**仅仅是移动 `Active Pointer` 指向既有的某个快照槽位**。
    * **严禁**通过把旧版本当成新版本重新写入，从而把 5 个槽位刷成同一种状态！
    * 例如：当前在 Slot3，回滚到 Slot1，此时 `Active Pointer` 指向 Slot1。若用户在 Slot1 和 Slot3 之间来回切换查看和测试，**5 个槽位的内容完全保持独立不变，绝不会耗尽缓存**。
  * **新演化分支覆盖**：只有当用户在回滚后的状态下，**做出了实质性的新修改并再次点击【保存演化】**时，系统才在当前指针之后开启新版本，淘汰最古老的一版快照。
* **回滚演化记录**：执行回退时，系统弹窗询问：“是否在演化日志中记入本次回退复盘？”供用户复盘总结。

## 四、 全局交互与安全性设计

### 4.1 全局编辑无损取消机制

* **原则**：任何正在进行中的编辑动作，用户随时有权无损还原，系统绝不提前污染底层数据源。
* **覆盖范围**：
  1. **画布节点拖拽**：在松开鼠标/手指前按下 `Esc`，或点击顶部【放弃本次排版】，所有节点瞬间弹回拖动前的原始坐标。
  2. **单个国策编辑弹窗**：弹窗底部明确提供【取消】与【保存】。点击【取消】立即关闭弹窗，不修改任何属性。
  3. **神圣座位个性化设置**：编辑过程中点击【取消】，还原所有输入框为数据库现存值。
  4. **下必为例判别弹窗**：在提交判例前点击【取消】，关闭弹窗且不产生脏数据。

### 4.2 破坏性操作二次确认保护

为彻底杜绝移动端误触与桌面端误按，所有破坏性操作设置强制二次防御门槛：

```
                    破坏性操作发起
                 (如点击【清零主链】)
                          │
                          ▼
            弹出居中警示模态框 (遮罩锁定背景)
        ┌────────────────────────────────────┐
        │ ⚠️ 严正警告：此操作不可撤销         │
        │                                    │
        │ 您确定要清零当前 #12 连胜纪录吗？    │
        │ 这将承认当前主链彻底断裂。          │
        │                                    │
        │   [再想想 (取消)]    [确认清零]     │
        └────────────────────────────────────┘
```

* **受保护的破坏性操作清单**：
  1. **神圣座位主链违规清零**（要求二次点击高危红钮，杜绝手滑）。
  2. **删除单个国策节点**（提示：“删除后，关联的有向连线将一并断开”）。
  3. **删除分组外框**（可选择：“仅删除外框保留组内节点” 或 “连同组内节点彻底删除”）。
  4. **删除连线**。
  5. **删除历史判例法记录**。
  6. **国策树版本回退确认**。

#### 1. 前端架构：Vue 3 + Vite + TypeScript + Pinia
* **框架底座**：`Vue 3` (Composition API, `<script setup>`) + `TypeScript` + `Vite`。
  * **选型理由**：启动毫秒级、构建产物极小、响应式心智模型简单。移动端渲染开销比 React 更轻量，非常适合在手机浏览器中秒开。
* **状态管理与路由**：`Pinia` + `Vue Router`。
  * `useSacredSeatStore`：管理专注倒计时、预约链、当前连胜节点；
  * `useFocusTreeStore`：管理画布节点状态、拓扑连线、当前选中与历史 5 槽位快照。
* **样式系统**：`Vanilla CSS + CSS Variables`。
  * 拒绝沉重的第三方 UI 组件库或繁琐的 Tailwind 编译链；
  * 用一套极简的 `:root[data-theme="dark"]` 与 `:root[data-theme="light"]` 原生变量，原生掌控黑白两套高对比自适应主题。

#### 2. 画布渲染中枢：`@vue-flow/core` (Vue Flow)
* **选型理由**：
  * Vue 3 生态下最成熟强悍的节点流程图库（React Flow 的官方 Vue 移植版）；
  * **开箱即用支持**：
    * 触摸屏手势（双指捏合缩放 Pinch-to-zoom、单指画布平移）；
    * 节点四向锚点磁吸连线；
    * 嵌套外框分组（Sub-flows / Parent Node）；
    * **内置正交折线布线算法**（`smoothstep` / `step` 路由算法，自动避开硬直拉线）；
    * 完全支持直接用 Vue 单文件组件写自定义节点卡片。

#### 3. 移动端 PWA 增强：`vite-plugin-pwa`
* 配置 Web App Manifest 与 Service Worker；
* 支持在 iPhone Safari（“添加到主屏幕”）和 Android Chrome（“安装应用”）中直接以**独立原生 App 窗口**运行，隐藏浏览器上下地址栏，提供全屏纯粹的专注氛围。

#### 4. 后端架构：Node.js (LTS) + Express (或 Fastify) + TypeScript
* **选型理由**：前后端统一使用 TypeScript，直接复用本文档第五节定义的强类型 Interface 数据模型（Schema），零沟通与转换成本。
* **职责分工**：
  * 提供轻量 RESTful API：`/api/focus-tree`、`/api/sacred-seat`、`/api/cases`、`/api/logs`、`/api/sync`；
  * 静态托管前端打包后的 `dist/` 文件；
  * 简单且安全的单用户访问鉴权：在服务器环境变量中设置 `APP_ACCESS_TOKEN`，前端首次进入输入一次即永久保存在 LocalStorage，防止公网被爬虫扫描或恶意篡改。

#### 5. 数据库持久化：SQLite (`better-sqlite3`)
* **选型理由**：
  * **单文件免运维**：整个数据库就是一个 `./data/app.db` 文件，内存占用不足 10MB，绝对不拖慢低配 VPS（免去单独运行 MySQL/PostgreSQL 动辄吃掉 300MB~500MB 宝贵内存的负担）；
  * **超高性能**：采用 WAL（Write-Ahead Logging）预写日志模式，单人使用场景下的读写延迟小于 0.1ms；
  * **灾备极简**：日常备份只需直接把 `app.db` 复制一份，或配置一个定时脚本把 db 文件加密推送到邮箱/网盘，实现数据高枕无忧。

### 6.2 从本地开发到云端上线的实施路径 (Roadmap)

#### 阶段一：本地全栈开发与联调 (Windows 本地)
1. **项目骨架初始化**：
   - 采用标准的前后端协同工程结构：
     ```text
     focus-tree-app/
     ├── frontend/              # Vue 3 + Vite + TypeScript + @vue-flow/core
     │   ├── src/
     │   │   ├── components/    # 节点卡片、分组外框、倒计时组件
     │   │   ├── stores/        # Pinia 状态树
     │   │   └── styles/        # 极简双模式 CSS 变量
     │   └── vite.config.ts
     ├── backend/               # Node.js + Express + SQLite
     │   ├── src/
     │   │   ├── db.ts          # better-sqlite3 初始化与表结构
     │   │   ├── routes/        # API 路由
     │   │   └── server.ts      # 服务端入口
     │   └── tsconfig.json
     ├── docker-compose.yml     # 生产环境一键编排
     └── Dockerfile
     ```
2. **本地联调启动**：
   - 前端启动 Vite 开发服务器：`http://localhost:5173`（配置 API Proxy 代理到 3000 端口）；
   - 后端启动开发模式：`http://localhost:3000`；
   - 本地完整验证神圣座位倒计时、国策树画布拖拽、下必为例录入与演化快照回滚。

#### 阶段二：服务器与域名准备指南
1. **云服务器选型（极低成本）**：
   - 推荐配置：**1核 2G 内存**（如腾讯云轻量应用服务器 / 阿里云轻量应用服务器 / UCloud / AWS Lightsail）；
   - 系统镜像推荐：**Ubuntu 22.04 LTS** 或 **Debian 12**；
   - 费用参考：国内各大云厂商活动机一般 60~120 元/年即可搞定（如需免 ICP 备案，可直接购买香港或新加坡节点）。
2. **个人域名配置**：
   - 购买任意便宜后缀域名（如 `.com` / `.top` / `.xyz`）；
   - 在域名 DNS 解析后台添加一条 **A 记录**（主机记录 `@` 或 `app`），直接指向你的云服务器公网 IP。

#### 阶段三：云端容器化生产部署 (Docker + HTTPS 自动化)
利用 Docker Compose，服务器上无需手动配置复杂的 Node.js 环境，一键拉起：

1. **生产级 Docker Compose 编排文件 (`docker-compose.yml`)**：
```yaml
version: '3.8'

services:
  app:
    build: .
    restart: always
    environment:
      - PORT=3000
      - APP_ACCESS_TOKEN=your_custom_strong_password  # 个人访问凭据
    volumes:
      - ./data:/app/data                              # 挂载 SQLite 数据库目录
    networks:
      - app-net

  nginx:
    image: nginx:alpine
    restart: always
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx/conf.d:/etc/nginx/conf.d
      - ./certbot/conf:/etc/letsencrypt                # 挂载 SSL 证书
      - ./certbot/www:/var/www/certbot
    depends_on:
      - app
    networks:
      - app-net

networks:
  app-net:
    driver: bridge
```

2. **免费 SSL 证书自动化 (Let's Encrypt)**：
   - 配合 `certbot` 容器自动申请免费 HTTPS 证书并设置定时自动续签，手机与电脑浏览器访问呈现安全绿锁；
   - 强制 HTTP 301 重定向跳转至 HTTPS。

3. **上线维护指令**：
   - 部署/更新只需在服务器项目目录下运行：
     ```bash
     docker compose up -d --build
     ```
   - 数据备份仅需拷贝宿主机上的 `./data/app.db`，实现真正意义上的“随时随地、永不丢数据、极简免运维”。
