# Sacred Focus｜把自制力方法变成可执行的日常系统

Sacred Focus 是一个本地优先的个人自制力实践网站。项目的设计灵感来自知乎用户 **Edmond** 对《如何提高自制力》的回答：它不把自制力理解为单纯“靠意志硬扛”，而尝试把目标、环境、规则、专注、复盘与长期迭代组合成一套可以每天使用的个人系统。

这里的界面、术语和实现是对该方法的个人化软件实践与延伸，并非对原回答的逐字转录、官方版本或任何效果承诺。

## 它试图解决什么问题

许多自律工具只解决“记录了多久”，却没有处理人在真正要开始、受到诱惑、失败后想放弃，以及长期目标逐渐失焦时会遇到的阻力。

Sacred Focus 将这些环节拆成可以操作的机制：

```text
明确要做什么
  → 降低开始阻力
  → 进入一段受保护的专注
  → 对行为给出清晰裁定
  → 复盘与保存数据
  → 更新下一轮目标系统
```

它不是医疗、心理治疗或诊断工具；更适合作为个人任务管理、专注训练和行为复盘的私有工作台。

## 核心方法如何落到产品中

### 1. 神圣座位：让“开始”成为一个明确动作

神圣座位是专注会话的入口。你可以写下本次目标、启动一个预设时长的倒计时，并进入沉浸式全屏；会话结束后，系统以实际物理时间记录结果。

- **主链**：成功专注会推进连续记录，帮助看见长期积累。
- **后悔窗口**：刚开始时允许撤销误触，避免偶发操作被过度惩罚。
- **预约链**：用较短的预约倒计时处理“现在还不想开始”的阻力，把启动任务缩小为一个更容易兑现的承诺。
- **历史与热力图**：查看会话、成功/失败/后悔状态以及长期投入分布，而非只依赖即时感受。

### 2. 国策树：把抽象愿望拆成可点亮的行动结构

国策树是目标系统的可视化画布。它由节点、分组、连线和说明标签组成：节点可以包含触发时间/场景、等级、失败条件、收益机制和备注；画布与列表提供两种管理视角。

- 在展示模式中点亮节点，记录当天已经完成的行动。
- 系统按凌晨 **04:00** 作为业务日界线处理连续性，而不是机械地以午夜切分。
- 编辑模式使用草稿和版本前置条件，降低多设备编辑时覆盖彼此工作的风险。
- 节点、分组与连线可以持续重排，让系统随现实变化，而不是一次性制定后被遗忘。

### 3. 下必为例：用预先写好的规则减少灰色地带

判例库用于记录“什么行为允许、什么行为禁止，以及适用的边界条件”。它的目的不是制造更多自我批评，而是把反复临场判断的问题提前写成可复用规则：当你面对诱惑或例外时，先回到已有裁定，而不是在当下为自己寻找借口。

判例支持筛选、编辑和导入导出，可逐步形成适合自己的行为边界库。

### 4. 演化与备份：允许系统迭代，也允许安全回退

一套个人方法必须能够调整。国策树提供 5 槽位环形演化快照，可为一次结构修改写下说明、导出架构，或回滚到先前版本。完整系统备份还会保存座位配置、会话日志、判例、树与演化数据，便于迁移和恢复。

重要写入使用 revision（乐观并发控制）；整机恢复会先创建 SQLite 热备，再在维护租约保护下执行事务性恢复。

## 一次典型使用流程

1. 在 **国策树** 中建立少量真正重要、能在当天执行的节点。
2. 当想开始又感到阻力时，先使用 **预约链**，或直接在 **神圣座位** 写下目标并启动专注。
3. 会话结束后如实记录结果；成功、失败和后悔是不同状态，不需要把它们混为一谈。
4. 遇到反复出现的诱惑、借口或例外，在 **判例法典** 中写下清晰边界。
5. 定期查看热力图、日志与主链；调整国策树，并在较大改动前创建 **演化快照**。

## 隐私与数据

项目采用本地 SQLite 存储业务数据，默认数据库位于 `DATA_DIR/app.db`；生产 Docker 部署会将其挂载到宿主机数据目录。系统不依赖第三方业务 SaaS，也不要求把专注日志同步到外部服务。

登录态使用 HttpOnly Cookie；请自行妥善设置生产环境密钥，并定期导出备份。不要将 `.env`、SQLite 数据库或 TLS 私钥提交到仓库。

## 技术实现

- 前端：Vue 3、TypeScript、Pinia、Vue Router、Vue Flow、Vite PWA。
- 后端：Node.js、Express、TypeScript、better-sqlite3。
- 交付：Docker Compose；可选 Nginx HTTPS 网关；支持数据库备份和可回滚更新。

```text
contracts/       前后端共享的纯类型契约
frontend/src/    Vue 页面、Pinia 状态、领域 gateway 与浏览器适配器
backend/src/     Express 接入、服务、repository、SQLite 基础设施与安全中间件
scripts/         构建、备份、更新、交付预检和运维手册
nginx/           可选 TLS 网关配置与本地证书辅助脚本
docs/            当前架构、模块、API/数据与开发说明
```

## 本地运行

要求：Node.js 22+ 与 npm。安装依赖后，分别启动后端和前端：

```bash
npm install
npm run dev:backend
npm run dev:frontend
```

前端开发服务器会把 `/api` 请求代理至后端。后端默认端口由 `PORT` 决定（默认 3000）；前端地址以 Vite 启动输出为准。

常用命令：

```bash
npm test                 # 跨端契约检查与后端回归测试
npm run build            # 构建前后端，并执行后端验证
npm run verify:delivery  # 无 Docker daemon 的交付静态预检（需要 Bash）
npm start                # 启动已构建的生产后端
```
